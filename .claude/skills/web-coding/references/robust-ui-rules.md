# 堅牢なコーディング（崩れないUI）のルール

このファイルは `AI-CODING-RULES.md` の 12章「堅牢なコーディング（崩れないUI）のルール」の内容を、
具体例・CSSプロパティ・JavaScript例を含めて意味・文言を変更せずそのまま移行したものです。

以下は、コンテンツ量の変化・実機の揺れ・将来の文言差し替えなどで見た目が崩れる事故を防ぐための実装ルール。
このプロジェクトは静的HTML/SCSS/Vanilla JSで、CMS・PHP・WordPressは使用しないため、CMS管理画面の条件分岐やWP_Query等のPHP固有ルールは対象外とし、静的サイトでも通用する部分のみ採用する。

## 画像・メディア

- 画像には`width`/`height`（または`aspect-ratio`）を明示し、読み込み前後でレイアウトが動く（CLS）のを防ぐ。
- 画像自体に`border-radius`を付ける（親のradiusだけに頼らない。はみ出した画像の角が四角のまま残る事故を防ぐ）。
- PC/SPで異なる画像（アートディレクション）を出し分ける場合は、`display:none`での出し分けではなく`<picture>`/`<source>`を使う（二重ダウンロードを避ける）。
- iframe（地図・動画埋め込み等）には`aspect-ratio`を指定し、読み込み前の高さ崩れを防ぐ。
- 画像が用意できない箇所は、不自然な代替素材を足さずプレースホルダーとして扱う。

## レイアウト・余白

- 要素の高さを固定値で決め打ちしない。内容量に応じて可変にする。
- 隣接する要素間の余白は、どちらか一方だけが`margin`を持つルールに統一する（両側が持つと二重になったり相殺で意図しない余白になったりする）。可能な場合は親の`gap`で余白を管理する。
- コンポーネント（カード・ボタン等）は自分の余白を自分で持ち、置かれる場所の余白に依存しない。
- 横並びのボタン・カード等は、`width`の決め打ちより`max-width`＋`flex`/`grid`で安全に縮む設計にする。
- `flex`/`grid`の子要素でテキスト省略（`line-clamp`等）や折り返しを使う場合は、子要素に`min-width: 0`（gridの可変列は`minmax(0, 1fr)`）を指定する。初期値の`min-width: auto`のままだと、中身の最小幅が親の枠を押し広げてしまう。
- カード一覧などで情報量に差がある場合、内容の高さで個別にズレるのではなく、行単位で上端・下端を揃える（CSS Gridの`subgrid`等）。画像・テキストが並ぶ行は、Grid/Flexで上端を揃え、単純な2カラム縮小に頼らない。
- アコーディオンなど開閉で高さが変わるUIは、`max-height`の決め打ちではなく`grid-template-rows: 0fr`⇄`1fr`のようにコンテンツの実高さに追従する手法を使う。
- リストのマーカー等、装飾目的の繰り返し要素は`::before`などCSSで出し、HTML側の繰り返し記述を減らす。
- 色・フォントサイズ・余白などの共通値はCSSカスタムプロパティ（またはSCSS変数）にまとめ、値の重複を避ける。
- 告知バーなど「出たり消えたりする」要素は、常に余白枠を予約するのではなく、要素自体に余白を持たせて「表示されている時だけ」余白ごと出る構造にする。

## タイポグラフィ・テキスト

- 本文に長い英単語・URL・メールアドレスが入る可能性がある箇所には`overflow-wrap: anywhere`を指定し、横スクロールやはみ出しを防ぐ。
- コピー年号のような日付情報は手書きで固定せず、JS（`new Date().getFullYear()`等）で自動生成する。
- 半角で統一すべき英数字・記号（電話番号、時間表記、チルダ「〜」、三点リーダー「…」等）は、見た目が似ていても文字コードが異なると検索・一括置換で取りこぼすため、プロジェクト内で使う文字・書式を1つに決めて統一する。
- 電話番号・住所など繰り返し登場する情報は、区切り記号や表記ゆれが出ないよう書式を1つに固定する。

## フォーム

- `input`/`textarea`/`select`には`box-sizing: border-box`と`max-width: 100%`を指定し、paddingを含めても親幅をはみ出さないようにする。

## ナビゲーション・固定要素（ヘッダー等）

- グローバルナビ等、項目数が増減しうる横並びメニューは、固定幅で詰め込まず`flex-wrap`で項目ごと折り返せるようにしておく。
- ヘッダー・ハンバーガーメニュー・ドロワー・ページトップボタンなど複数の固定（`position: fixed`/`sticky`）要素がある場合は、場当たり的に大きい数字を足すのではなく、先に`z-index`の階層表を決めてから実装する。
- ページ内アンカーリンクがある場合、クリック時のJSだけに頼らず、`scroll-margin-top`等のCSSで「別ページからの直リンクやURL直接アクセスでも固定ヘッダーに見出しが隠れない」仕組みにする。

## リンク・パス

- サイト内リンク・画像パスは環境（開発/本番、公開先ディレクトリの変更等）に依存しない書き方（ルート相対パス等）にし、ドメインを直書きしない。
- 電話番号は`tel:`リンクにする。メールアドレスを本文に直書きで公開する場合はスパム収集対策（JSでの組み立て表示等）を検討する。
- カード等の「リンク範囲」は、後から変更しやすいよう主要タグにクラス名を付け、CSSをタグ名・階層構造に依存させない。

## JSの安全性・外部ライブラリ

- 複数ページで共通に読み込むJSは、対象要素が存在しない場合に備えてガード節（`if (el) { ... }`）を入れ、1つの要素が無いだけで他の機能まで止まらないようにする。
- カルーセル/スライダー等を使う場合、表示件数が0件・1件になりうるなら件数で分岐し、不要な操作UI（pagination等）やライブラリのエラーが残らないようにする。
- 外部ライブラリ（CDN）は`@latest`などバージョン未指定で読み込まず、検証済みのバージョンに固定する。
- 自前のCSS/JSにキャッシュ対策のクエリ（`?v=...`）を付ける場合は、アクセスごとに変わる値ではなく、更新したタイミングだけ変える。
