# 【将来WordPress等のCMSを導入する場合のみ適用】CMS/PHP固有ルール

このファイルは `AI-CODING-RULES.md` の 13章の内容を、関数名・条件を省略せずそのまま移行したものです。

このプロジェクトは現時点では静的HTML/SCSS/Vanilla JSで、WordPress等のCMSは使用していないため、以下は**今は適用しない**。将来的にWordPress化・CMS化する場合にのみ参照し、該当する機能を実装する際に反映すること。AIは、CMS導入の指示がない限りこの章の内容を実装に反映してはいけない。

- **投稿本文の画像サイズ**：CMSの投稿本文（`the_content`）に入る画像は、`width:100%`ではなく`max-width:100%` + `height:auto`にする。`width:100%`だと、WordPressが自動付与する`height`属性が残って画像が縦に伸びたり、小さい画像まで拡大されたりする。アイキャッチ等「枠いっぱいにしたい画像」は本文画像と別クラスで扱う。
- **投稿本文の基本スタイル**：投稿本文用に`.entry-content`等の基底クラスを用意し、`h2`〜`h6`・リスト・リンク・引用・画像・表などCMS側で自由に使われうる要素をまとめて整える（見出しの一部だけ調整済みで他が素のまま、という状態を避ける）。
- **一覧の抜粋（excerpt）**：手入力・カスタムフィールド由来の抜粋文にHTMLタグが混ざる可能性があるため、一覧表示用にはタグを除去してプレーンテキスト化してから出す（`wp_strip_all_tags()` + `esc_html()`等）。
- **CMS項目の表示条件**：カスタムフィールド等の値は未入力でも出力される前提で考え、値がある時だけラベルごと出す（`if`で囲んでから出力する）。空のラベルだけが残る事故を防ぐ。
- **CMS動的値のエスケープ**：CMSから出す動的値は出力先ごとに無害化する——表示テキストは`esc_html`、`href`/`src`は`esc_url`、`alt`/`title`等の属性値は`esc_attr`、許可HTMLは`wp_kses_post()`。入力値をそのままHTMLへ流さない。
- **一覧の0件状態**：記事・お知らせ等の一覧は0件になる前提で組み、`have_posts()`の`else`で「現在、○○はありません」等の空状態メッセージを出す。見出しだけ残って本文が真っ白にならないようにする。
- **アイキャッチ未設定時の代替**：アイキャッチ画像は未設定になる前提で組み、`has_post_thumbnail()`の`else`で共通のノーイメージ画像を表示し、画像枠の比率とカード高さを全投稿で揃える。
- **一覧の可変件数・最終行**：CMS一覧はぴったりの件数で終わらない前提で組む。半端な件数の最終行の寄せ方（左寄せ等）と、記事が増えた時のページネーションを最初から用意する。可変列のカードグリッドは、少数件でもカードが不自然に拡大しないよう`auto-fill`（空き列を残す形）を使う。
- **ページネーション**：記事一覧とページネーションの件数基準をズレさせない。`pre_get_posts`でメインクエリの表示件数を変更し、一覧用とページ数判定用に別々の`WP_Query`を使わない。
- **NEWバッジ**：手動フラグで付け外しせず、公開日（`get_the_time('U')`等）と現在日時の差から自動判定し、期限を過ぎたら自動的に消えるようにする。
- **カテゴリの色分け**：カテゴリバッジは基底クラスだけで完成する見た目にし、既知のカテゴリは色だけ上書きする。クライアントが新しいカテゴリを追加しても、素の文字のまま表示される事故を防ぐ。
- **フォントの文字セット**：CMSで今後増える人名・地名・記号まで見込んだ広い文字セットか、動的サブセット配信を使う。公開時点で使われている文字だけに絞ったフォントサブセットは避ける。
- **詳細ページを持たないカスタム投稿**：詳細ページ（single）を意図的に作らないカスタム投稿タイプがある場合、URLが自動生成されて検索結果に出てしまわないよう、シングルURLを一覧へ301リダイレクトし、サイト内検索（`exclude_from_search`）とXMLサイトマップの両方からも除外する。
