# Webコーディング 基本ルール

このファイルは `AI-CODING-RULES.md` の 1章・2章・4章・5章・6章・7章・8章・9章・10章・11章の内容を、
意味・文言を変更せずそのまま移行したものです（対応関係は `SKILL.md` および作業報告の対応表を参照）。

## 1. 基本方針

- 指示された範囲・目的を正確に理解してから実装する。
- 指示されていない変更を勝手に追加しない。
- 既存の仕様・挙動を変更しない。
- 判断できない仕様や不明点がある場合は、推測して実装せず確認する。
- 「より良くする」という理由だけで、依頼されていない変更を行わない。

## 2. 命名規則

### BEM記法

クラス名はBEM記法を使用する。

- `block`：独立したUIのまとまり
- `block__element`：Blockの中にある部品
- `block--modifier`：BlockまたはElementの状態・見た目・バリエーションを表す場合に使用する

例：

```html
<header class="header">
  <h1 class="header__title">...</h1>
</header>
```

状態やバリエーションがある場合：

```html
<header class="header header--fixed">
```

```html
<button class="button button--large">
```

`--modifier` は、同じBlockまたはElementの状態やバリエーションを表す場合に使用し、単に別の要素を作る目的では使用しない。

### JavaScript

JavaScriptの変数・関数名はcamelCaseを使用する。

```js
const headerTitle = "...";

function getHeaderTitle() {
  // ...
}
```

## 3. 既存コードについて

- 既存コードの書き方・構成・設計を優先する。
- 勝手なリファクタリングを行わない。
- コードを「きれいにする」「効率化する」ことだけを目的とした変更は禁止。
- 同じ処理を複数箇所に記述する必要がある場合でも、既存の実装パターンを確認してから対応する。
- 既存の仕様・挙動を変更しない。

## 4. 変更範囲

依頼された箇所のみを変更する。

例えば、

「ヘッダーを修正してください」

という指示の場合、ヘッダー以外の箇所に問題を発見しても、勝手に修正しない。

別の箇所に修正が必要と思われる問題を発見した場合は、

1. その問題を報告する
2. 影響範囲を説明する
3. 修正が必要か確認する

という順番で対応する。

## 5. 変更前の確認

コードを変更する前に、以下を確認する。

- 現在の実装
- 関連するHTML / SCSS / JavaScript
- 既存の仕様・挙動
- 変更による影響範囲
- 変更が他のページ・セクション・コンポーネントに影響しないか

変更範囲が不明確な場合は、推測して進めず確認する。

## 6. セキュリティ

実装時には、セキュリティ上の問題がないか確認する。

特に以下に注意する。

- ユーザー入力をそのままHTMLやJavaScriptに出力しない
- 必要に応じて入力値をバリデーション・サニタイズする
- 外部から取得したデータを無条件に信頼しない
- APIキー、パスワード、トークンなどの機密情報をコードやGitに含めない
- `.env` などの機密ファイルをGit管理しない
- 危険なHTML・JavaScriptの挿入を行わない
- 既存のセキュリティ対策を削除・弱体化しない

セキュリティ上の問題を発見した場合は、実装内容とあわせて報告する。

## 7. Git操作

AIは以下の操作をユーザーの明示的な指示なしに行ってはいけない。

- commit
- push
- merge
- rebase
- reset
- branchの削除
- force push

Gitの変更が必要な場合は、まず変更内容を説明し、ユーザーの確認を待つ。

## 8. 判断に迷う場合

以下のような場合は、AIが勝手に判断して実装しない。

- Figmaから読み取れないデザイン仕様
- 仕様が複数通り考えられる場合
- 文言や画像が不明な場合
- レスポンシブ時の挙動が不明な場合
- 既存仕様と新しい指示が矛盾している場合
- 変更範囲が不明な場合
- 既存コードを変更する必要性が判断できない場合

この場合は、質問して確認する。

## 9. 作業完了時の報告

すべてのコーディングが完了したら、このブランチで今回の作業によって変更した内容をすべて報告する。

報告には以下を含める。

- 変更したファイル
- 変更した内容
- 新しく追加したもの
- 削除したもの
- 既存コードへの変更
- 仕様・挙動への影響
- セキュリティ上確認したこと
- 未対応・確認が必要な事項

AIが行っていない変更については、今回の作業で行った変更として報告しない。

## 10. 実装方針

基本的に以下の順番で作業する。

1. 指示内容を確認する
2. 関連する既存コードを確認する
3. Figma・仕様・既存実装を確認する
4. 変更による影響範囲を確認する
5. 不明点があれば質問する
6. 指示された範囲のみ実装する
7. 実装結果を確認する
8. 必要に応じて修正する
9. 作業完了後、変更内容を報告する

AIは、ユーザーから明示的に依頼されていない作業を「ついでに」行わないこと。
